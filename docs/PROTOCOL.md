## 设备识别

| VID | PID | 官方映射 |
| --- | --- | --- |
| `372E` | `1029` | S9 Pro，有线（`is4G: false`） |
| `372E` | `1026` | EWEADN S9，无线共享接收器 |
| `372E` | `103D` | Gaming 2.4G，无线共享接收器 |

共享接收器也用于 S9 Max、Ultra 等型号，因此还需要核对 `getUUID()` 返回的设备型号标识 `9895604649998`，十六进制为 `09 00 00 00 00 0E`。固件或硬件版本若使用其他标识，需要根据诊断结果适配；本版不猜测未知标识。

仅访问以上 VID/PID 且 UsagePage 位于厂商区（`FF00`–`FFFF`）、FeatureReportByteLength 至少 64 的 HID collection。使用 report ID `03`。不读取普通鼠标输入报告。

## 查询

Windows `HidD_SetFeature` 的缓冲区首先放 report ID，然后放官方编码的 63 字节请求。编码载荷包含：校验和、命令类型 `50`、写数据长度、分包编号、主命令、子命令/偏移，以及剩余零填充。校验和是载荷中除校验字节外的求和低八位。

| 查询 | 主命令 | 子命令 | Windows 请求前七字节 |
| --- | --- | --- | --- |
| 型号标识 `getUUID` | `4F` | `80` | `03 1F 50 00 00 4F 80` |
| 电量 `getBasics` | `4F` | `81` | `03 20 50 00 00 4F 81` |
| 无线在线状态 `checkWirelessOnline` | `47` | `00` | `03 97 50 00 00 47 00` |

官方库每次发送 Feature 后间隔 100 ms 尝试读取。工具每次最多两轮发送、每轮最多四次读取；这些次数限制不构成底层 Windows IOCTL 的硬性超时。查询在后台串行运行，避免阻塞托盘线程或重叠操作；句柄在每轮轮询后释放。

**Feature 响应保留 report ID**，应直接解析 Windows 缓冲区，不能套用普通 InputReport 去除 report ID 的逻辑。官方 v2.1 响应布局：report ID（0）、命令类型（1）、ACK（2）、数据长度（3）、分包编号（4）、偏移（5）、数据（6 起）。SDK 验证 ACK 为零和分包编号匹配；工具另外验证 report ID、偏移及数据长度，以拒绝其他查询的旧响应。该协议没有请求序列号，无法完全排除其他程序对相同查询造成的竞争。

用户在 2026-10-08 捕获的真实报文确认：请求偏移 `80` 对应响应偏移 `00`，请求 `81` 对应响应 `01`，即响应偏移不含读取位 `80`；数据长度可为 **11 字节**。SDK 的 `RES_PACKET_LIMIT_SIZE: 10` 是请求分包的编码默认值，不能作为响应长度上限。1.0 版错误地要求偏移原值回显且长度不超过 10，导致有效的无线和有线响应均被拒绝；1.0.1 修正并加入真实报文回归测试。响应的数据长度仅按缓冲区实际容量和各查询最小长度校验。

第二份诊断确认：不带子命令的在线查询 `47` 在响应偏移字段返回主命令 `47`，而非请求的占位值 `00`。真实响应前缀 `03 50 00 0B 00 47 01` 表示在线。1.0.1 错误地校验此字段为零，导致无线读取在查询在线状态时中止；1.0.2 使用 `47` 并拒绝在线查询期间收到的旧型号（偏移 `00`）或电量（偏移 `01`）响应。

型号数据至少八字节：前两字节协议版本，后六字节按大端序组成型号标识。电量数据至少七字节：第一字节低七位为百分比，高位为充电标志；百分比超过 100 视为无效响应。无线在线数据第一字节为 0 或 1。无线离线时不将可能缓存的电量标成新读数。

第二份日志中的有线基本信息前缀 `03 50 00 0B 00 01 E4`，其中 `E4` 解码为充电标志为真、原始数值为 100；无线基本信息前缀 `03 50 00 0B 00 01 4E` 的电量为 78，与网页一致。充电模式下的 100 不能视为实际满电。本版保留原始数值供诊断，但在充电标志为真时，将百分比标为不可靠，隐藏数字并抑制满电提示。没有确认独立的充电完成字段，不根据时间、拔线或充电标志消失推断完成；非充电状态下明确读取到 100 才提示电量达到 100%。

参考：[微软 HidD_GetFeature 文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hidsdi/nf-hidsdi-hidd_getfeature)、[Chromium HID 接口关于 Feature 响应保留 ID 的说明](https://chromium.googlesource.com/chromium/src/+/0bcb839d1077216ccc4661e5e3e94430c0e326fb/services/device/public/mojom/hid.mojom)。

## 网页充电展示与主动事件的进一步检查

检查上述官方 3.3.2 代码得到以下结果，不需要等待新的充满日志即可确认：

- 主页面设备状态卡明确针对 `solutionRovider == "beiying" && battery.charging` 禁止显示百分比（`showPercentage: !K && !R`，其中 `R` 是这个条件）。电池组件在充电且百分比隐藏时显示“充电中”。因此 S9 Pro 网页隐藏百分比是明确的界面逻辑。
- S9 Pro 使用的 `base.getBasics()` 只解析百分比和 `isCharging` 两项充电相关信息，没有解析独立的充电完成字段。已检查的设备状态卡、贝盈适配层和底层基本信息/事件解析均未找到“已充满”的专用判断；这不等于证明固件不存在未公开的能力。
- SDK 另有主动上报途径：`FA` 主动消息下的事件编号 `5` 进入 `BatteryChange`，解析器只返回载荷首字节数值；贝盈网页适配层收到事件后把它写为 `battery.level`，并无条件将 `charging` 设为 `false`（源码是 `Boolean(void 0)`），不是读取充电完成位。不能把这段适配代码直接当作可靠的充满判断。
- 1.0.2 及以前只查询 Feature 报告，未监听主动 InputReport；1.1.0 已加入监听和接收器补充读数。事件是否发出、是否在实际满电时变化仍需设备验证。静态代码可以说明网页怎么解析，不能单独证明实际固件会在物理充满时发出什么。

## 1.1.0 充电电量研究

- 有线充电时继续独立查询接收器：先确认 S9 Pro 型号标识，再检查在线状态，最后查询基本信息。仅采用充电标志为假的接收器百分比，标明来源“接收器”，同时保留有线实际充电标志；不会复制充电前缓存的无线数字，也不会把接收器充电中的 100 当成真实电量。适配目标仍为一只 S9 Pro。
- 型号确认后，使用 Windows 的物理设备 `ContainerId` 将其他厂商 collection 关联到查询设备。仅监听同一物理设备的厂商 UsagePage；缺少容器标识时只监听确切已验证的查询 collection，不根据相同 PID 猜测归属。普通鼠标、键盘 collection 不打开。设备断开或监听失效后，该监听器保存的候选值不再用于显示。
- Native InputReport 缓冲区包含 report ID；其后的 `FA 05 <level>` 是 SDK 的 BatteryChange 事件。官方 SDK 不要求 InputReport ID 与 Feature ID 相同。用模拟 InputReport 对照官方 SDK 确认 `FA 05 4E` 发出电量事件 78。工具允许不同 input ID，但只在已验证的厂商 collection 上解析。
- 原始电量事件会进入诊断日志。0–100 的值可以进入候选记录，但充电时的 100 不作为显示数字或通知依据；超出范围的原始事件仅保留诊断，不猜测高位含义。事件不含独立充电完成标志，不采用网页适配层无条件清除充电标志的逻辑。
- 单独有线充电时，新事件的低于 100 的数值显示为“上报…（待核实）”，不是已经确认准确的电量。只接受本次已识别充电期间接收、且在 90 秒内的事件；时间显示为上报接收时间，不声称是设备内部测量时间。操作系统缓冲中积压的事件可能缺少原始时间，因此该通道仍需实际验证。
- 充电期间 Feature 查询间隔缩短到 15 秒，事件到达后可刷新已有状态而不重复发送查询。输入流使用可取消的异步读取，失败后重试；关闭工具时取消监听。监听通道能力、接收报告计数、原始电量事件计数、最近有效值及错误可导出，不要求等充满才进行诊断。
- 时间估算仅使用可信来源（目前为独立接收器查询）的连续充电读数：至少三个不同电量值、跨度至少三分钟、累计增加至少三个百分点，按 `(100 - 当前百分比) × 已观察分钟数 ÷ 已增加百分点` 计算并向上取整。使用最近 30 分钟窗口；断开、待核实事件、超过三分钟的数据空档或电量下降会清空样本。结果标为近期速度估算，后段速度变化不能由这一线性模型预测。未获得连续可信数据时不输出分钟数。

Windows 接口依据：[HID collection 的用户态读取](https://learn.microsoft.com/windows-hardware/drivers/hid/opening-hid-collections)、[FileStream 异步读取](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.readasync)、[设备容器关联](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/devpkey-device-containerid)。

官方[中高配说明书](https://file.eweadn.cn/product-pdf/S9中高配八国说明书-新.pdf)封面包含 S9 Pro、Max、Ultra、Ultra+，中文“电量状态指示”写明充电红灯常亮、充满绿灯常亮。这是硬件完成的可观察信号；现有 USB 查询和事件没有暴露对应的独立字段，灯变绿不意味着程序可以直接读取灯的状态。本说明书为图片 PDF，已查看原始页面确认，未将 S9 V2 的说明替代原版。

优先验证方案：

1. 如接收器具有 USB-A 插头，将它直接插入电脑另一个端口，原装数据线连接鼠标。如果接收器是独立 Type-C 接口的 8K 型号，则需要另一根数据线。1.1.0 已支持同时查询，验证重点是鼠标进入有线后接收器是否仍报告在线和变化的真实电量。
2. 如果普通有线连接停用无线通信，可尝试在电脑 USB 供电与鼠标之间使用只供电、不传数据的连接，同时将模式开关保留在 2.4G 并连接接收器。这可能避免 USB 有线模式接管，但固件也可能按供电状态切换或同样上报充电占位值。必须在电量低于 100% 时确认无线在线、读数有效且充电时增长，不能保证此方案适用于实际固件。保持电脑 USB 供电，接收器自身仍需正常数据连接。
3. 若无法同时实时读取，可在充电期间短暂拔下鼠标线、接回接收器取得明确电量，然后恢复充电。将来若展示该读数，必须标注“上次无线读数”及时间，不能伪装为当前充电百分比，也不能仅因达到 100% 判定硬件结束充电。

## 1.2.0 提醒方式

提醒改为工具自己的 WinForms 无边框窗口，不通过 `NotifyIcon.ShowBalloonTip` 或系统 toast 接口发送。使用 `ShowWithoutActivation`、`WS_EX_NOACTIVATE`、`WS_EX_TOOLWINDOW` 与 `WM_MOUSEACTIVATE` 的 `MA_NOACTIVATE` 避免弹出和点击时抢占输入焦点。定位到主屏幕 `WorkingArea` 右下角，尺寸按 DPI 调整。系统“仅优先通知”的横幅筛选不负责该窗口；独占全屏、锁屏等情况仍可能使其不可见。依据：[Form.ShowWithoutActivation](https://learn.microsoft.com/dotnet/api/system.windows.forms.form.showwithoutactivation)、[不激活窗口的输入处理](https://devblogs.microsoft.com/oldnewthing/20160912-00/?p=94295)。当前开发环境只能编译 Windows 程序，尚未实测 Windows 桌面显示、焦点行为和不同 DPI。

低电量通知策略独立于 HID 通信：可信在线非充电电量严格低于阈值时提醒一次；充电开始或电量恢复到阈值加 3（上限 100）才重新允许下一次提醒。断开、休眠和错误读数不触发也不重新允许提醒；候选充电事件不触发。设置及开关在本地 JSON 保存，预览不更新提醒去重状态。100% 提醒保留原有可信读数规则，改变窗口显示方式没有增加固件完成信号。

## 1.2.1 透明圆角与减少重复工作

此前 `Region(GraphicsPath)` 将窗口形状裁切为整像素区域，即使内容使用抗锯齿，窗口最外沿仍会出现台阶。1.2.1 改为 `WS_EX_LAYERED` + `UpdateLayeredWindow` + `AC_SRC_ALPHA`，采用 top-down 32bpp 预乘 alpha DIB。绘图到两倍尺寸后缩小，再直接写入 DIB；透明度与淡入由 blend 的 `SourceConstantAlpha` 调整，不混用 `Form.Opacity` / `SetLayeredWindowAttributes`。淡入过程复用同一个 DC 和 DIB，不在每帧分配原生句柄。依据：[UpdateLayeredWindow](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-updatelayeredwindow)、[BLENDFUNCTION](https://learn.microsoft.com/windows/win32/api/wingdi/ns-wingdi-blendfunction)、[CreateDIBSection](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-createdibsection)。

卡片内容只在弹出和尺寸/DPI 改变时绘制；取消持续重绘倒计时条。入场约 180ms 期间计时器为 30ms，随后为 250ms，仅检查悬停、显示区域变化和自动关闭，不重绘卡片。关闭时停止计时器，先释放包装 DIB 内存的 Bitmap，再恢复 DC 原对象、删除 DIB 和 DC。

托盘图标为四倍尺寸绘制后缩小的圆角徽标；同一时刻只保存当前 Icon，以数字、百分比、充电状态、颜色和尺寸为缓存键。读数时间改变不再生成 Icon，也不因每次 5 秒状态检查而绘制。设备描述列表缓存 30 秒；手动刷新、设备变更和恢复通过原有 `force` 路径使缓存立即失效；30 秒扫描是事件丢失时的兜底，不改变 60/15 秒电量查询规则。这些修改已通过 Windows 交叉编译和核心回归测试，实际桌面边缘效果及资源占用仍需 Windows 实测。

## 1.2.2 只提醒观察到的充电过程

`ChargeNotice` 的首个新鲜读数只初始化基线，不触发提醒；如果初始为可信 100%，后续重复读数或拔插仍不提醒。如果初始正在充电且尚未可信满电，则记录正在进行的充电过程。有线占位值 `E4` 只能用于记录充电标志，不能触发提醒；之后收到可信的 100% 才通知一次。短暂断开、休眠、查询失败保留等待状态，但不触发通知；非充电可信读数不足 100% 结束等待。通知后保持已达 100% 的标记，可信读数不足 100% 才解除，再次提醒还需观察到充电。状态只存在当前运行内，不在重启后还原；重新启用 100% 提醒也重新建立基线。候选事件、低电量策略和预览行为不变。

## 1.2.3 无线事件及时更新

`S9Battery-diagnostics-20261012-115831.zip` 显示：11:57:50 无线 Feature 电量字节 `61`（97）；11:58:20 主动事件 `09 FA 05 62`（98）；11:58:27 手动查询返回 `62`（98）。此前 `ApplyEvent` 仅处理充电候选读数，普通无线事件虽被记录并触发 UI 刷新，却未应用到状态，因此数字必须等定期或手动查询才改变。日志也记录了设备原始值在 97 与 98 之间反复变化，不能将所有 1% 差异归因于工具，也不能仅靠日志确认固件报数波动的原因。

新增 `WirelessEvent` 来源，仅在已经查询确认在线的无线非充电连接上使用。事件须来自当前型号验证通过的查询设备，数值 0–100，接收时间不在未来、不早于 90 秒前，且严格晚于当前电量读数时间。接受后保存电量和接收时间，保持原有查询计划及最近在线校验时间；后续查询优先于旧事件。已接受的值不会因为监听样本过期而回退；断开、休眠、错误时仅保留为上次读数，不用事件恢复在线；有线和充电占位值规则不变。事件同样参与低电量提醒去重，不凭无线电量上涨建立充电过程。
